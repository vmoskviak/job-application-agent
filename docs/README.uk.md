# jobsearch-autopilot

Автоматизований пошук роботи в Німеччині для кількох людей одразу. Щовечора
агент збирає нові вакансії з порталів і кар'єрних сторінок, відсіює
невідповідні, пише під кожну CV й Anschreiben. Щоранку подає заявки поштою
та через портали, розбирає відповіді роботодавців і шле оператору звіт.

Рушій тут, у цьому репозиторії. Дані людей (резюме, документи, трекер,
заявки) лежать окремо, у приватному репозиторії, по папці на клієнта.

## Як це влаштовано

```
jobsearch-autopilot/            цей репозиторій: код, тести, шаблони
  bot/                          скрапери, фільтри, рендер CV, подача на порталах
  docs/agents/*.md.j2           промпти вечірнього й ранкового агента
  scripts/server/               cron-обв'язка
  templates/client/             скелет папки нового клієнта
  examples/clients/erika/       вигадана кандидатка: приклад і тестова фікстура

jobsearch-clients/              приватний репозиторій з даними
  clients/<slug>/
    profile.yaml                контакти, поля форм, статус
    cv.yaml                     досвід, освіта, скіли, вкладення
    tracks.yaml                 які ролі шукаємо і яким CV на них подаємось
    targeting.yaml              локації, виключення, пороги
    search.yaml                 пошукові запити й кар'єрні сторінки
    accounts.yaml               поштові скриньки, браузерний профіль
    candidate_brief.md          вільний текст для написання листів
    attachments/ applications/ tracker.md
```

Один процес працює з одним клієнтом. Клієнт обирається змінною
`JOBSEARCH_CLIENT` або прапорцем `--client <slug>` у будь-якій команді.
Поле `status` у `profile.yaml` (`active`, `paused`, `placed`) вирішує, чи бере
клієнта cron.

Агент працює на Claude Code у headless-режимі. Python робить усе, що можна
перевірити тестом: перевірку, чи вакансія жива, скоринг, фільтри, дедуплікацію
проти трекера, рендер документів, заповнення форм порталів. Claude пише
пошукові запити й тексти листів і читає пошту.

## Що вміє

| Етап | Що відбувається |
|---|---|
| Пошук | Perplexity, кар'єрні сторінки, StepStone за фасетом, Indeed через Firecrawl, job-алерти з пошти |
| Відбір | перевірка, що вакансія ще відкрита; трек за ключовими словами; виключення за назвою ролі; локація; дублікати проти трекера |
| Пакет | CV у PDF і DOCX у потрібному варіанті, Anschreiben, список Anlagen |
| Подача | email із вкладеннями; StepStone «Schnelle Bewerbung», XING Easy Apply, Interamt і кілька корпоративних ATS; решта йде оператору списком із прямими лінками |
| Відповіді | Eingangsbestätigung, відмова, запрошення на співбесіду; нагадування по заявках без відповіді |
| Порядок | авто-ghost після 45 днів тиші, видалення папок закритих заявок, ротація логів |

Рушій розрахований на німецький ринок: портали, формат заявки й мова листів.

## Швидкий старт

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/playwright install chromium
.venv/bin/python -m pytest -q                 # тести йдуть на examples/clients/erika

export JOBSEARCH_CLIENTS_DIR=/шлях/до/jobsearch-clients/clients
.venv/bin/python -m bot.clients list
.venv/bin/python -m bot.onboard init anna     # скелет нового клієнта
.venv/bin/python -m bot.onboard check --client anna --render
```

Далі: [docs/onboarding.md](onboarding.md) про те, як завести людину,
[docs/server_setup.md](server_setup.md) про сервер і cron,
[docs/architecture.md](architecture.md) про рішення в коді.

## Чого тут немає

Жодних токенів, паролів і персональних даних. OAuth-токени пошти й браузерні
профілі з логінами порталів лежать лише на машині запуску, у `~/.gmail-mcp` і
`~/.playwright-mcp`. API-ключі читаються зі змінних оточення.

## Перш ніж запускати на живій людині

Заявки йдуть від імені реальної людини реальним роботодавцям. Потрібна її
явна згода й доступ до двох поштових скриньок і акаунтів на порталах. Перший
запуск робиться в режимі `APPLY_MODE=dry-run`: агент готує все, але нічого не
відправляє. Автоматична подача через портали може суперечити їхнім умовам
користування, це ризик власника акаунта.
